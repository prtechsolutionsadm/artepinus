# Artepinus · Site e sistema

`/` é o site institucional público (`src/app/(site)`, rotas públicas em `src/proxy.ts`); o sistema entra por `/sistema`, a tela de início com a escolha do módulo. A manutenção está em teste (`MODULOS_EM_TESTE` em `src/lib/permissoes.ts`): aparece "Em breve" para todos e abre só para o ADMIN; para liberar a todos, mova para `MODULOS_ATIVOS`. Avisos com link da manutenção só vão para quem enxerga o módulo (`notificar()`). Não apague o código dela.

Next.js 16 (App Router) + Prisma 7 (client gerado em `src/generated/prisma`) + Prisma Postgres (`DATABASE_URL` = string TCP direta; local com `npm run db:local`). Interface e código em português.

- Driver escolhido em `src/lib/adaptador.ts`: `@prisma/adapter-ppg` (serverless) para `db.prisma.io` — na Vercel um pool TCP por instância estoura o limite de conexões; `@prisma/adapter-pg` com pool pequeno para Postgres local. Não troque de volta para TCP em produção. Na Vercel o Preview usa o mesmo `DATABASE_URL` da produção: `scripts/migrar.mjs` e o seed não rodam com `VERCEL_ENV=preview`; as migrations rodam antes do `next build` da produção, então precisam ser compatíveis com o código anterior (coluna nova opcional ou com default).

- Checks: `npx tsc --noEmit` e `npm run build`.
- Erros: `error.tsx`/`global-error.tsx` em português; Server Action chamada do cliente (transition, onClick) vai num try/catch com `mensagemFalha()` de `src/lib/falha-acao.ts` (relança redirect/notFound, mostra "Sem conexão"). Parâmetro de URL/busca vira número só por `inteiroPositivo()` e data por `diaValido()` (`src/lib/constantes.ts`); nas actions, `z.iso.date()`.
- Mudou `prisma/schema.prisma`? Rode `npx prisma migrate dev --name <nome>` e commite a migration.
- Mutations ficam em `src/app/actions/*` (Server Actions validadas com zod; sempre checar permissão com `exigirPermissao`/`pode` de `src/lib/permissoes.ts`).
- Módulos: Manutenção (`perfil`; `SEM_ACESSO` = não usa) e Produção (`perfilProducao`; Admin/Gerente sempre têm). Páginas de manutenção usam `exigirModulo("manutencao")`/`exigirPermissao`; as de produção `exigirProducao(acao)`, e as actions `podeProducao(eu, "lancar" | "gerir")`. Menus por módulo em `src/lib/menu.ts`.
- Rastreabilidade: Pacote (`numero` → código `PCT-000123`, helpers em `src/lib/rastreio.ts`) ligado a boletim/ciclo e a um `Pedido`; boletim ⇄ cargas e ciclo ⇄ boletins são m2m; carga → floresta/fornecedor/motorista (colheita/talhão só em dados antigos). Toda mudança de pacote cria um `EventoPacote` (a linha do tempo do QR).
- Ficha de madeira (formato do papel da fábrica): uma linha = espessura + larguras marcadas (125/100/85/50 ou Mista) + peças por comprimento (2,50/2,10/1,65/1,30/1,00/0,70). Mesmo formato na serraria (`lancarLote()`), no ciclo da estufa (com grades úmidas) e no inventário: `FichaMadeira` (edição), `TabelaFicha` (leitura), helpers `itensDaLinha`/`linhasDosItens`/`linhasParaTabela` em `src/lib/producao.ts`. Cada linha vira um item por comprimento (campo `linha` agrupa); m³ usa a média exata das larguras marcadas (Mista = média de todas); o campo `largura` guarda a média arredondada, só para exibição. Cada `Lote` (`LOT-000123`, etiqueta QR + code128) tem um pedido; a classe (Ótimo/Bom/Regular) sai do comprimento. Cada estufa tem a ficha mensal em `/producao/estufas/[id]`. Meta/horas do boletim vêm de `ConfigSerraria` (id "padrao"), somente leitura.
- Offline: apontamentos (carga, lote, inventário) usam `enviarOuGuardar()` de `src/lib/fila-offline.ts` (IndexedDB, `chaveOffline` para idempotência) e sincronizam por `/api/offline`; páginas offline em `PAGINAS_OFFLINE` de `public/sw.js` (mudou o que o SW guarda? suba a versão do cache). Cada item da fila tem dono (`usuarioId`): só sincroniza com o mesmo usuário logado; item recusado pelo servidor fica parado com o motivo até "Tentar de novo" ou "Descartar".
- Navegação (padrão do sistema Engemase, pedido do cliente): `MenuLateral` enxuto (marca + "Artepinus · módulo" no alto, leva a /sistema; grupos abrem/fecham pela setinha, lembrado em localStorage; rodapé só com "Recolher menu"; recolhível só com ícones: `data-menu="recolhido"` no <html> via `SCRIPT_MENU` + localStorage, largura em `--largura-menu`) + `TopoApp` em `src/components/Navegacao.tsx`. Computador: logo no menu lateral (no topo só em /sistema, `semMenuLateral`; o logo sempre leva a /sistema), "← Voltar" (sobe para a tela de cima; some nas telas iniciais e em /sistema), busca no meio (atalho "/"), "Módulos" (/sistema, para quem tem mais de um módulo ou `podeAdministrar`), tema, ajuda, avisos e usuário ▾ só com Meu perfil e Sair. Faixa verde compacta (cartão, não de largura total). Celular: topo simples + `BarraInferior`; "Mais" (/menu) com cartões (`TodasAsTelas` só ali). Telas iniciais e hubs (/producao, /manutencao, /sistema, /administracao) usam `src/components/painel` (`FaixaPainel`, `SobreFaixa`, `GrupoAtalhos`, `CartaoAtalho`, `CartaoPrincipal`, `TodasAsTelas`); cada `ItemNav` de `src/lib/menu.ts` tem `descricao` para os cartões. Interface simples: cada função vê só o que usa. Verde em degradê fixo (não muda no escuro): classe `fundo-marca`; faixa de largura total: utilitário `sangria` + `MedidaRolagem`. Barras de rolagem finas na cor do sistema (globals.css).
- Manual do usuário em `src/lib/manual/` (ids de seção fixos = /ajuda/<id>#tópico; `rotas` ligam cada tela ao "?" do topo). Mudou uma tela? Atualize o tópico no mesmo commit, rode `npm run manual:validar` e, se a tela tem captura, `npm run manual:capturas` (servidor local com `SEED_DEMO=1`; capturas da Manutenção num build local com ela em `MODULOS_ATIVOS`) e commite `public/ajuda/`.
- Versão e notas de atualização: `NOTAS` em `src/lib/versao.ts` (mais nova no topo; `VERSAO` = a primeira) → tela `/novidades`, cartão Novidades em /sistema e versão no rodapé (`Rodape novidades`). Publicou mudança que o usuário percebe? Nova entrada em linguagem simples + `version` do package.json igual (`npm run manual:validar` confere).
- Triagem do período de teste: `src/app/actions/triagem.ts` (só ADMIN, Cadastros → Configuração #triagem; também no Painel Administrativo). A rotina das 7h só gera preventivas e lembretes com a Manutenção em `MODULOS_ATIVOS`.
- Site: fotos reais em `public/site/` (abertura, floresta, toras, serraria, estufa, pacotes .jpg) via `<Foto nome>` de `src/components/site/Foto.tsx`; sem a foto, aparece uma ilustração. Topo transparente sobre a foto só na página inicial (`CabecalhoSite`).
- Tema escuro: classe `.dark` no `<html>` (`src/components/Tema.tsx`, salvo em localStorage); `globals.css` remapeia a paleta (stone/marca/status e `--color-white` = superfície) só na tela — impressão/PDF ficam claros. Use as classes de cor normais do Tailwind; painel claro dentro de área `text-white` precisa da classe `superficie`.
- PDF das fichas: `BotaoPdfFicha` (jsPDF no navegador) via prop `pdf` da `TabelaFicha`.
- Inventário: "Madeira em" é por linha da ficha (`ItemEstoque.local/estufaId`); o local do `LevantamentoEstoque` só existe nos antigos.
- Expedição: toda saída gera um `Romaneio` (`ROM-000123`, motorista/placas copiados do cadastro) — PDF em `BotaoPdfRomaneio`; peças comuns dos PDFs em `src/lib/pdf-cliente.ts`. Relatório mensal em PDF: `BotaoRelatorioMensal` (dados de `painelProducao`).
- Paradas na hora (`ParadaMaquina`, `src/lib/paradas.ts`, actions em `src/app/actions/paradas.ts`, tela `/producao/paradas`): "Máquina parou" só para `Equipamento.linhaSerraria`; MEC/ELE abre requisição na hora (`criarRequisicaoCompleta(..., { semParada: true })`). Requisição com máquina parada numa máquina da linha cria a parada (`refletirRequisicaoNaParada`, chamada na criação e em `atualizarStatus`); início/fim acompanham `paradaInicio/paradaFim`. Ao fechar, `lancarParadaNoBoletim()` grava uma `ParadaProducao` (com `paradaMaquinaId`) por dia, só com o tempo dentro do turno (`ConfigSerraria.turnoInicio/turnoFim`); abre sozinha o boletim de cada dia útil (seg–sex, até hoje) com tempo parado (marcado com `MARCA_BOLETIM_PARADA` nas observações e auditado; enquanto vazio, o primeiro lote o passa a quem lança) — sábado/domingo só entram se o boletim existir ou for aberto depois (`sincronizarParadasDoDia`). Excluir a parada também desliga `maquinaParada` da requisição. O formulário do boletim não edita nem apaga essas linhas.
- Alertas da serraria (`src/lib/alertas-serraria.ts`, via `notificar()`): estufa passou da previsão (`alertaAtrasoEm`), dia útil sem apontamento (cron 18h `/api/cron/serraria`) e pedido pronto (`prontoAvisadoEm`, checado ao concluir ciclo/formar/expedir). Crons em `vercel.json` precisam de `CRON_SECRET`.
- QR do pacote (`/p/[numero]`) é rota pública (`PREFIXOS_PUBLICOS` em `src/proxy.ts`): visitante vê o resumo PT/EN sem dados internos (cliente, pedido, pessoas, fornecedor, placas); equipe logada é redirecionada à tela interna (`?publico=1` força a versão pública). Etiquetas novas usam `Pacote.codigoPublico` (aleatório, `novoCodigoPublico()`); o número no QR só vale para visitante se `qrLegado` (etiquetas antigas).
- Painel da TV em `/tv` (fora do layout do app, exige login): `src/lib/tv.ts` + `router.refresh()` a cada 60 s e Wake Lock.
- Pedidos: `volumeM3`/`prazo`; situação (serrado, verde, estufa, seco, expedido, saldo, pronto) só por `situacaoPedidos()` em `src/lib/pedidos.ts` (soma no banco; também usada no aviso de pedido pronto e na aba Pedidos dos cadastros). Telas `/producao/pedidos` e `/producao/disponivel` (estoque livre × reservado).
- Declaração de origem por romaneio (PT/EN): `BotaoDeclaracaoOrigem` com dados de `origemDosPacotes()`. É declaração da empresa, não certificado oficial: não use "certificado/certify" nesse documento (o PDF traz o aviso de que não substitui documentos fiscais, ambientais ou fitossanitários).
- Zerar movimento de teste: `zerarMovimento()` (só ADMIN, Cadastros → Configuração) faz TRUNCATE ... RESTART IDENTITY nas tabelas de movimento (`MOVIMENTO` em `src/app/actions/cadastros.ts`) e, se marcado, em pedidos, `CADASTROS_ORIGEM` e `MOVIMENTO_MANUTENCAO`; mantenha as listas atualizadas ao criar tabelas de movimento.
- Roteiros por função para imprimir: `src/lib/roteiros.ts` → `/ajuda/roteiros`.
- Segurança: login limitado por `src/lib/limite-tentativas.ts` (5 erros por login / 20 por IP em 15 min, tabela `TentativaLogin`; a tentativa é gravada antes de conferir com `reservarTentativa()` e descartada no sucesso, o que fecha rajadas em paralelo; na recuperação pela pergunta também 10 erros por login em 24 h, e o dono e os ADMIN são avisados); login inexistente gasta o mesmo tempo (bcrypt com hash falso). Sessão JWT leva `versao` = `Usuario.versaoSessao` — trocar/redefinir senha ou desativar incrementa e derruba as outras sessões; sessão inválida passa por `/sair` (apaga o cookie). Toda Server Action precisa checar o usuário (podem ser chamadas de qualquer página, inclusive públicas). Cabeçalhos de segurança em `next.config.ts`; crons conferem o segredo com `cronAutorizado()`.
- LGPD: Política de Privacidade em `/privacidade` (pública); prazos de guarda em `RETENCAO` (`src/lib/retencao.ts`), aplicados todo dia por `limparRegistrosAntigos()` na rotina `/api/cron/lembretes` — mude a política junto. Recuperação de senha pública em `/recuperar` (pergunta de segurança, `src/lib/perguntas.ts`).
- Textos: não use a palavra "Produção" em rótulos/títulos da interface (pedido do cliente); a pasta/rotas `/producao` continuam.
- KPIs só por `calcularKpis()` (`src/lib/producao.ts`); OEE = Disponibilidade × Produtividade (sem Qualidade); m³ das bitolas é calculado no servidor (mm → m³). Datas de boletim são `@db.Date` ("AAAA-MM-DD" via `diaParaDate`/`dateParaDia`).
- Mudanças de status sempre geram um registro em `HistoricoStatus`.
- Datas: o servidor roda em UTC; use os helpers de `src/lib/constantes.ts` (horário de Brasília).
- Toda ação que altera dados registra em `Auditoria` via `auditar()` de `src/lib/auditoria.ts`.
- Nova requisição: `criarRequisicaoCompleta()` em `src/lib/requisicoes.ts` (usada pelo formulário e pela fila offline `/api/requisicoes/offline`).
- Fotos passam por `processarFoto()` (sharp: 1600px, JPEG, sem EXIF) e são servidas por `/api/anexos/[id]` só para logados.
